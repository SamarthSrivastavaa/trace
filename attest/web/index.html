Evidence-bound messaging

Every sentence is a claim somebody has to answer for.

An AI-written customer message is self-asserted. Nobody reading “this is our final attempt” can tell whether it is the final attempt, whether the offer exists, or whether it expires when the sentence says it does. The truth is not in the text.

Attest freezes the merchant's authoritative state, lets the model propose only what the message claims, and has deterministic code decide whether each claim survives its evidence. Every decision writes a proof anyone can recompute offline, without asking us to be trusted.

Three authorities, never blurred.

Most systems collapse extraction, judgement and truth into one confident sentence. Attest keeps them apart everywhere — in the type system, in this interface, and in what it refuses to say.

01 — the model

What it may say

A claim: its kind, the span of text it covers, the value it asserts, and a citation into the frozen snapshot. The schema has no field for a verdict, so a model attempting to state one fails to parse. It is not trusted to abstain from deciding — it is unable to.

02 — the code

What it decides

Whether each asserted value matches the evidence it cited, in the snapshot frozen before the model ever saw it. No network, no database, no clock, no randomness. The same claim against the same snapshot returns the same verdict, permanently.

03 — neither

What is never claimed

That the message is true in the world. Only that every checkable claim in it resolved against recorded state under a recorded policy. A qualitative promise this system cannot express is not verified, and is not reported as though it were.

Same words.
Different truth.

The message is byte-identical in both runs. One field in the merchant's subscription record differs. That is the entire difference, and it is enough to invert the outcome — because the sentence was never the evidence.

Approval is not delivery

SEND means no deterministic reason to block or escalate was found. It does not mean anything was delivered. Attest never observes a transport, so a SEND proof writes no send record; only a caller reporting real delivery consumes the cooldown.

Replay needs no permission

Re-verification recomputes the decision from the stored snapshot under the policy recorded with that proof. It does not re-ask the model and makes no network call. Anyone holding the database can run it and disagree with us.
